# Motion Spec — Take-up Tension (Torque Control) และขั้นตอน Empirical Calibration

> สร้าง 2026-08-05 จากเอกสารออกแบบ motion ที่ user ยืนยันความถูกต้องแล้ว
> (`motion_design_source_mentor.md` §4.2, §4.3, §4.6 + §6)
>
> ไฟล์นี้เป็น **ขั้นตอนปฏิบัติ (procedure)** สำหรับหาค่า torque setpoint จริง
> เหตุผลเชิงออกแบบว่าทำไมต้องเป็น torque control และทำไมเลือกมอเตอร์ตัวนี้

## 1. ทำไมต้องหาค่าด้วยการทดลอง (ไม่ใช่คำนวณ)

ค่าที่ระบบต้องการจริงคือ torque setpoint ที่ทำให้ `F_tension` พอดี:

```
Torque = F_tension × r(t)
```

แต่ **`F_tension` ที่ "พอดี" สำหรับเทปเฉพาะทางตัวนี้ ยังไม่มีใครรู้ค่า** และคำนวณล่วงหน้าไม่ได้
เพราะค่าจริงรวมสิ่งที่วัดแยกชิ้นไม่ได้เข้าไปด้วย:

- แรงเสียดทานของระบบส่งกำลังและแบริ่งทั้งชุด
- ความแข็ง/ความยืดของเทปจริง และแรงที่ทำให้ชิ้นงานเริ่มขยับใน pocket
- ผลของ mounting จริงและการจัดแนว

**วิธีที่ใช้:** ใช้ servo drive เป็นเครื่องมือวัดในตัว แทนการมี load cell แยก
(เหตุผลเต็มอยู่ใน ADR-008 ข้อ 3) — ค่าที่ได้จึงเป็น **empirical calibration ของระบบจริงทั้งระบบ**
และใช้เป็น ground-truth parameter ป้อนกลับเข้า simulation model ของ Digital Twin ได้ทันที

## 3. ขั้นตอน (ที่มา §4.6)

```
1. ตั้ง Torque Limit ไว้ต่ำ ๆ ก่อน                    ← ข้อ 2 ตารางด้านบน
2. สั่ง torque command เริ่มจากค่าน้อย (~5–10% ของ rated)
3. ค่อย ๆ เพิ่มทีละนิด พร้อมสังเกตพฤติกรรมเทปด้วยตา:
      เทปหย่อน / ตก                     → torque น้อยไป  → เพิ่ม
      เทปตึงจน pocket บิด / ชิ้นงานขยับ  → torque มากไป   → ลด
4. เมื่อเจอจุด "ตึงพอดี" อ่านค่า torque/current ที่ drive รายงาน
      (หน้าจอ drive / ASDA-Soft / Modbus register ผ่าน Rust layer)
5. ทำซ้ำที่ขนาดม้วนต่าง ๆ กัน: core → กลางม้วน → เต็มม้วน
      เพื่อดูว่า torque setpoint ค่าเดียวพอไหม หรือช่วงต้น/ปลายต้องขยับ
```

**เกณฑ์ตัดสิน "ตึงพอดี" คือการสังเกตด้วยตา ไม่ใช่ตัวเลข** — บันทึกสิ่งที่เห็นไว้ด้วย
ไม่ใช่บันทึกแค่ตัวเลข torque

## 4. ตารางบันทึกผล (ยังไม่มีข้อมูล — กรอกเมื่อทำจริง)

| รอบที่ | วันที่ | ขนาดม้วน (core / กลาง / เต็ม) | เส้นผ่านศูนย์กลางม้วนที่วัดได้ (mm) | torque command (% ของ rated) | torque/current ที่ drive รายงาน | สิ่งที่สังเกตเห็นที่เทป | สรุป |
|---|---|---|---|---|---|---|---|
| _ยังไม่ได้ทำ_ | | | | | | | |

**ผลลัพธ์ที่ต้องได้จากการทดลองนี้:**

| ค่า | สถานะ | ใครรอใช้ |
|---|---|---|
| torque setpoint ที่ใช้งานจริง (normal operating torque) | ❌ ยังไม่มี | `machine_spec.md` ข้อ 3 (motion profile) + ข้อ 6.2 (ต้องต่ำกว่า Safe Torque Limit พร้อม margin) |
| ต้องชดเชยตามขนาดม้วนหรือไม่ (ค่าเดียวพอไหม) | ❌ ยังไม่มี | ตัดสินว่าต้อง implement สูตร `r(t)` ในข้อ 5 หรือไม่ |
| `r₀` (รัศมี core) และรัศมีม้วนตอนเต็ม | ❌ ยังไม่มี | สูตร `r(t)` + `bom-cost` (ขนาด core) |
| ความหนาเทปต่อชั้น (`thickness`) | ❌ ยังไม่มี | สูตร `r(t)` |

> ห้ามเติมตัวเลขสมมติลงตารางนี้เพื่อให้ดูครบ — ช่องว่างที่ทำเครื่องหมายไว้ปลอดภัยกว่าตัวเลขที่เดา

## 5. การชดเชยตามขนาดม้วน (ทำต่อเมื่อข้อ 4 บอกว่าจำเป็น)

ถ้าผลทดลองพบว่า torque setpoint ค่าเดียวไม่พอตลอดทั้งม้วน ให้ประมาณรัศมีแบบ open-loop:

```
r(t) = √( r₀² + (thickness / π) × L(t) )
```

| ตัวแปร | ได้มาจากไหน | สถานะ |
|---|---|---|
| `r₀` | วัดจากแบบ CAD / ของจริง | ❌ ยังไม่มี |
| `thickness` | ความหนาเทปต่อชั้น — วัดจากเทปจริง | ❌ ยังไม่มี |
| `L(t)` | **คำนวณได้ฟรีจาก feed encoder ที่มีอยู่แล้ว** — นับจำนวนรอบ feed × 18 mm หรืออ่านสะสมจาก encoder ที่ measuring roller โดยตรง | ✅ มีทางได้อยู่แล้ว |

**ข้อดีของวิธีนี้:** ไม่ต้องเพิ่มเซนเซอร์วัดขนาดม้วนเลยแม้แต่ตัวเดียว
**ข้อควรระวัง:** เป็นการประมาณแบบ open-loop — ถ้าเทปพันไม่แน่นสม่ำเสมอ ค่าจะเพี้ยนสะสม
