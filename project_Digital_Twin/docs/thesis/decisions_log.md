# Decisions Log — บันทึกการตัดสินใจ

> ทุกการตัดสินใจ + เหตุผล + ทางเลือกที่ไม่ได้เลือก → เอาไปเขียนบทที่ 3 และ 5 ของรูปเล่ม
> เขียนตอนตัดสินใจเลย อย่ารอถึงตอนเขียนเล่มแล้วมานั่งนึก

## 2026-06-23 — เลือก RS PRO Counter แทนการนับพัลส์ด้วย MCU ตั้งแต่แรก

**เลือก:** ใช้ RS PRO Counter (20 kHz, รองรับ A+B quadrature) ในช่วง prototype

**ทางเลือกที่ไม่ได้เลือก:** ให้ STM32 อ่าน encoder เองด้วย timer ตั้งแต่ต้น

**เหตุผล:**
- ลดความเสี่ยงฝั่ง firmware ในช่วงที่กลไกยังไม่นิ่ง
- debug ง่ายกว่า — เห็นตัวเลขบนหน้าปัดโดยตรง แยกปัญหากลไกออกจากปัญหาโค้ดได้
- รองรับ quadrature ในตัว ไม่ต้องเขียน decode เอง

**ผลที่ตามมา:** ต้องมีแผนย้ายไป STM32F401 (timer-based decoding) หลัง validate กลไกแล้ว

**อ้างอิง:** `docs/adr/ADR_001_encoder_counter.md`

## 2026-06-23 — ไม่ใช้ physics engine ในการทำ Digital Twin

**เลือก:** ควบคุมการเคลื่อนไหวใน 3D ด้วย FSM + transform ตรง ๆ

**ทางเลือกที่ไม่ได้เลือก:** cannon-es / ammo.js / rapier

**เหตุผล:** เครื่องจักรอัตโนมัติเป็น deterministic, state-driven, timing-controlled
cylinder extend/retract, feeder step, sealing timed — ไม่มีอะไรต้องจำลองแรง
physics เพิ่มความซับซ้อนโดยไม่ได้ความแม่นยำที่ต้องการ

**เงื่อนไขที่จะกลับมาทบทวน:** ถ้าต้องจำลอง part drop / collision / jam analysis / training simulation

**อ้างอิง:** `ARCHITECTURE_3D_TWIN.md` ข้อ 9

## 2026-07-27 — แยกพอร์ต Rust bridge เป็น 8767

**ปัญหาที่เจอ:** `gateway_fsm_upgrad.py` ต่อออกไปที่พอร์ต 8766 ซึ่งเป็นพอร์ตเดียวกับที่จอ
TouchGFX ต่อเข้ามา → กลายเป็น client ทั้งคู่ ไม่มีใคร listen ต่อกันไม่ติด
**อาการที่เห็น:** เปิด `upgrad` แล้วจอขึ้นเลข 0 หมดทุกช่อง

**แก้:** แยกเป็น 8766 (จอ) / 8767 (Rust) + ปิด Rust bridge เป็นค่าเริ่มต้น (`RUST_BRIDGE=1`)
+ retry ทุก 3 วิ (ของเดิม reconnect ทุก 20 ms ตอนบอร์ดไม่ได้เสียบ)

**บทเรียนที่เอาไปเขียนบทที่ 5 ได้:** ในระบบหลายเลเยอร์ ต้องกำหนดให้ชัดตั้งแต่ออกแบบว่า
**ใครเป็น server ใครเป็น client** ในทุกช่องทางสื่อสาร — จึงเป็นที่มาของการทำ `port_map.md`
เป็นเอกสารสัญญาแยกออกมาต่างหาก

## 2026-07-27 — ทอยผลตรวจกล้องครั้งเดียว ไม่ทอยซ้ำในลูป

**ปัญหา:** สเต็ป VISION เช็ค `step_allowed == True` ในลูป 20 ms → ทอยความน่าจะเป็นใหม่ทุกรอบ
ระหว่างรอ operator กด เด้ง ALARM ~78% ภายใน 2 วินาที กด PASS แทบไม่ทัน

**แก้:** ทอยครั้งเดียวตอนกล้องตรวจเสร็จ แล้วค้างผลไว้รอคนตัดสิน

**บทเรียนเชิงหลักการ:** เหตุการณ์ที่ควรเกิด "ครั้งเดียว" ห้ามวางไว้ในลูปที่รันทุก tick
