# ติดตั้งบนเครื่อง PC ใหม่

## เตรียมเครื่อง (ทำครั้งเดียว)

1. ติดตั้ง Python 3.10+ — ติ๊ก ☑ *Add python.exe to PATH*
2. ติดตั้งไลบรารี:
   ```bash
   pip install websockets pyserial
   ```
3. ก๊อปโฟลเดอร์ repo `dt-taping-dev` ทั้งก้อนไปเครื่องใหม่
   (ชื่อเดิม `TestWab-main` **เลิกใช้แล้ว** — โค้ดถูกยกมาอยู่ใน repo นี้หมดแล้ว)
   - ต้องมี: `python_backend/`, `cad/`, `start_demo.bat`
   - ตัดทิ้งได้: `rust_bridge/target/` (ไฟล์ build เก่า ไม่จำเป็น)
4. เสียบสาย USB บอร์อง (ช่อง ST-LINK) — Windows 10/11 ลงไดรเวอร์ VCP ให้เองตอนเสียบครั้งแรก
   - ถ้า COM port ไม่ขึ้นใน Device Manager → ลง STM32CubeProgrammer หรือ STSW-LINK009 หนึ่งครั้ง
5. **ไม่ต้องลง** TouchGFX Designer / STM32CubeIDE / Rust — firmware อยู่ใน flash บอร์ดแล้ว ลงเฉพาะตอนจะแก้หน้าจอ HMI

## ใช้งาน (ทุกครั้ง)

ดับเบิลคลิก **`start_demo.bat`** — เปิดให้ครบ 3 ส่วน:

| ส่วน | คำสั่ง | หน้าที่ |
|---|---|---|
| Gateway FSM | `python gateway_fsm.py` | สมองกลหลัก, SQLite, พอร์ต 8765/8766 |
| Serial Bridge | `python serial_bridge.py` | เชื่อมจอบอร์ด STM32 ผ่าน USB (ถ้าไม่เสียบบอร์ด ปิดหน้าต่างนี้ทิ้งได้) |
| Web Server | `python -m http.server 8000 -d cad` | เว็บ 3D Twin ที่ `http://localhost:8000/index1.html` |

ปิดระบบ: ปิดหน้าต่างดำทั้ง 3 บาน หรือรันคำสั่ง PowerShell นี้ (ปิดเฉพาะ process ของโปรเจกต์)

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe' or Name='pythonw.exe'" | Where-Object { $_.CommandLine -match 'gateway_fsm|app_vision|serial_bridge|http\.server' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

🔴 **ห้ามใช้ `taskkill /F /IM python.exe`** — คำสั่งนั้นฆ่า Python **ทุกตัวในเครื่อง**
รวมงานอื่นที่ไม่เกี่ยวกับโปรเจกต์นี้เลย (เอกสารฉบับก่อนหน้าเคยแนะนำคำสั่งนี้ — เลิกใช้แล้ว)
รายละเอียด + วิธีเช็คว่าปิดหมดจริงไหม → [`docs/RUNBOOK.md`](docs/RUNBOOK.md) ข้อ 4

## การสั่งงานเอาต์พุตลงบอร์ดจริง (Modbus coil write)

หัวข้อนี้ว่าด้วย **`start_all.bat`** (ตัวเปิดระบบครบทุกชั้น ไม่ใช่ `start_demo.bat` ข้างบน)
ลำดับการเปิดทีละชั้นแบบ manual + ของที่ต้องเห็นในแต่ละชั้น อยู่ที่
[`docs/RUNBOOK.md`](docs/RUNBOOK.md) ข้อ 2 — ที่นี่พูดเรื่องเดียวคือ
**ทำยังไงให้คำสั่งเขียน coil ออกไปถึงบอร์ดจริง**

### 1. ค่าตั้งต้นคือ read-only และตั้งใจให้เป็นแบบนั้น

`start_all.bat` **ไม่เขียนอะไรลงบอร์ดเลย** ถ้าไม่ได้สั่งเพิ่ม — ในโค้ดตั้ง
`ALLOW_WRITE=0` และ `RO_FLAG=1` ไว้เป็นค่าเริ่มต้น แล้วส่ง `RUST_READ_ONLY=1`
เข้าไปให้ `rust_modbus_bridge.exe` ซึ่งจะ**บล็อกเฟรม `0x0F` (Write Multiple Coils) ทุกเฟรม**

เหตุผล: firmware บนบอร์ด `192.168.0.100` **ไม่มี source code สำรองอยู่ที่ไหนเลย**
พังแล้วเอาคืนไม่ได้ ค่าตั้งต้นจึงต้องปลอดภัยที่สุดไว้ก่อน
รายละเอียดว่าอะไรยิงใส่บอร์ดได้บ้าง → [`docs/specs/board_protocol.md`](docs/specs/board_protocol.md)
· ข้อห้ามเรื่องบอร์ดตัวนี้ → [`docs/RUNBOOK.md`](docs/RUNBOOK.md) ข้อ 6.6

🔴 **ห้ามแก้ค่าตั้งต้นในสคริปต์ให้เป็น write** — วิธีที่ถูกคือใส่ flag ตอนสั่งรันเป็นครั้ง ๆ ไป

### 2. อาการเวลาลืมใส่ `--write` — จุดที่คนหลงทางมากที่สุด

เปิดด้วย `start_all.bat 2` เฉย ๆ (ไม่ใส่ flag) แล้วจะเจอแบบนี้:

- ✅ หน้าต่างขึ้นครบทุกบาน ไม่มี error
- ✅ กล้อง OpenMV ทำงาน จอ STM32 ขึ้นตัวเลขจริง
- ✅ FSM เดินครบทุกสเตป นับชิ้นงานได้ครบทั้งล็อต
- ✅ Rust ต่อบอร์ดติดจริง (`netstat` ขึ้น `ESTABLISHED` ไป `192.168.0.100:502`)
- 🔴 **แต่ไฟบนบอร์ด Modbus ไม่ติดเลยสักดวง**

**นี่ไม่ใช่บอร์ดเสีย และไม่ใช่สายหลุด** — ระบบทำงานถูกต้องทุกอย่าง เพียงแต่คำสั่งเขียน
ถูกบล็อกไว้ที่ชั้น Rust ตามค่าตั้งต้น ไม่มีอะไรออกไปถึงขา output ของบอร์ด

ที่ทำให้งงเป็นพิเศษคือ **ถ้าไม่ใส่ `--write` สคริปต์จะข้ามคำถามยืนยันไปเลย ไม่ถามอะไรสักคำ**
(บรรทัด 89 ของ `start_all.bat` `goto safety_done` ทันที) คนกดเลยไม่มีทางรู้ว่ามีด่านนี้อยู่

### 3. ขั้นตอนเปิดแบบเขียน coil ได้จริง

**ขั้นที่ 1** ปิดของเดิมให้หมดก่อน (ดับเบิลคลิก `stop_all.bat` ที่รากของ repo)
ห้ามเปิดทับของเก่า — พอร์ตจะชนกันแล้วชั้นที่ต้องเขียนจะถูกข้าม

**ขั้นที่ 2** เปิดหน้าต่าง cmd: กด `Win+R` พิมพ์ `cmd` แล้ว Enter

**ขั้นที่ 3** ย้ายไปที่โฟลเดอร์ repo (ต้องมี `/d` เพราะเป็นการข้ามไดรฟ์)

```cmd
cd /d E:\work-TE-Project\project_Digital_Twin\dt-taping-dev
```

**ขั้นที่ 4** สั่งรันพร้อม flag `--write`

```cmd
start_all.bat 2 --write
```

**ขั้นที่ 5** สคริปต์จะขึ้นกรอบเตือนแล้วถามกลับ ให้พิมพ์คำว่า `WRITE` แล้ว Enter

```cmd
WRITE
```

> โค้ดเทียบด้วย `if /i` คือ **ไม่สนตัวพิมพ์ใหญ่เล็ก** — `write` หรือ `Write` ก็ผ่านเหมือนกัน
> แต่ต้องเป็นคำว่า write เท่านั้น พิมพ์ `y` หรือ Enter เปล่า ๆ ไม่ผ่าน

**ทางลัดบรรทัดเดียว** — หัวไฟล์ `start_all.bat` ระบุว่าทุกคำถามรับ piped input ได้
จึงป้อนคำตอบล่วงหน้าได้เลย (เหมาะกับตอนเปิด-ปิดซ้ำหลายรอบ)

```cmd
echo WRITE | start_all.bat 2 --write
```

### 4. วิธียืนยันว่าเปิดโหมดเขียนติดจริง

**ในหน้าต่างที่สั่งรัน** ต้องเห็นบรรทัดนี้

```
-> coil writes ENABLED for this run.
```

🔴 ถ้าเห็นบรรทัดข้างล่างนี้แทน แปลว่า**พิมพ์คำยืนยันไม่ตรง** ระบบยังเป็น read-only อยู่
ให้ปิดด้วย `stop_all.bat` แล้วเริ่มขั้นที่ 2 ใหม่

```
-> not confirmed. Staying READ-ONLY.
```

ตรวจซ้ำได้อีก 2 จุด:

- **บรรทัดสรุปท้ายสคริปต์** ต้องขึ้น `SAFETY : RUST_READ_ONLY=0 - COIL WRITES TO THE BOARD ARE LIVE.`
- **หน้าต่าง `DT-RUST-BRIDGE 8767`** — ต้อง**ไม่มี**บรรทัดนี้โผล่ขึ้นมา (ถ้ามีขึ้น คือยังโดนบล็อกอยู่)

```
RUST_READ_ONLY=1 : coil write (0x0F) DISABLED - read-only frames only
```

### 5. ไฟบนบอร์ดควรกระพริบ ไม่ใช่ติดค้าง

พอเปิดโหมดเขียนได้แล้ว **อย่าคาดหวังว่าไฟจะติดค้างสว่างตลอด** — ปกติคือ **กระพริบเป็นจังหวะ**
เพราะ FSM มี 17 สเตป แต่มีแค่ **3 สเตปเท่านั้นที่ส่งสัญญาณออก** (และต้องอยู่ในสถานะ
`running` ด้วย — กด Start บนหน้าเว็บหรือบนจอแล้ว)

| สเตป | ค่า `op0` | บิตที่ติด | สัดส่วนเวลาโดยประมาณ |
|---|---|---|---|
| `FEED_CARRIER` | `0x01` | bit 0 | ~10% |
| `SEAL_PROCESS` | `0x02` | bit 1 | ~10% |
| `TAKEUP_REEL` | `0x04` | bit 2 | ~10% |
| `ALARM` | `0x08` | bit 3 | เฉพาะตอนมี alarm |
| อีก 13 สเตปที่เหลือ | `0x00` | ไม่มีไฟติด | ~70% |

**สรุป: ประมาณ 70% ของเวลา ไฟดับหมดทุกดวงเป็นเรื่องปกติ** ถ้าเฝ้ามองแค่แป๊บเดียวแล้วไม่เห็นอะไร
ให้ดูต่ออีกสัก 20-30 วินาที (ตัวเลขสัดส่วนข้างบนมาจากการสุ่มอ่านค่าจริง 20 วินาที)

ที่มาของตรรกะนี้: [`python_backend/gateway_fsm_upgrad.py:602-608`](python_backend/gateway_fsm_upgrad.py)

### 6. ตารางสรุป flag และโหมดของ `start_all.bat`

**โหมด** (ใส่เป็นตัวเลขตัวแรก ถ้าไม่ใส่จะขึ้นเมนูให้เลือก)

| โหมด | เปิดอะไรบ้าง | ใครกด PASS / NG |
|---|---|---|
| `1` FULL DEMO | rust_bridge + gateway_fsm_upgrad + web + HMI simulator | คนกดเองบนจอ HMI |
| `2` VISION TEST | เหมือนโหมด 1 + `app_vision.py` (กล้อง OpenMV) | กล้องส่ง `DECISION` มาเอง |
| `3` LIGHT | `gateway_fsm.py` + web server เท่านั้น | ไม่มี rust bridge / ไม่แตะบอร์ดเลย |

> โหมด `3` ข้ามด่านความปลอดภัยทั้งหมด เพราะไม่มีชั้นที่คุยกับบอร์ดตั้งแต่แรก
> ใส่ `--write` ไปก็ไม่มีผลอะไร

**flag** (ใส่ต่อท้ายได้หลายตัว ไม่สนตัวพิมพ์ใหญ่เล็ก)

| flag | ทำอะไร | ไม่ใส่แล้วเป็นยังไง |
|---|---|---|
| `--write` | เปิดทางให้เขียน coil `0x0F` ลงบอร์ด (**ยังต้องพิมพ์ `WRITE` ยืนยันอีกชั้น**) | 🔴 read-only — ทุกอย่างเดินครบแต่**ไฟบนบอร์ดไม่ติด** และ**ไม่มีคำถามใด ๆ ให้ตอบ** |
| `--kill` | ตอบ "ใช่" ให้อัตโนมัติ เมื่อเจอ process เก่าค้างพอร์ตอยู่ (ฆ่าทิ้งแล้วยึดพอร์ต) | สคริปต์หยุดถามว่าจะฆ่าไหม |
| `--nokill` | ตอบ "ไม่" ให้อัตโนมัติ — ปล่อยของเก่าไว้ แล้ว**ข้าม**ชั้นที่พอร์ตไม่ว่าง | สคริปต์หยุดถาม |
| `--nopause` | ไม่ค้างหน้าจอ `pause` ตอนจบ (ไว้เรียกจากสคริปต์อื่น) | ค้างรอกดปุ่มก่อนปิดหน้าต่าง |

ตัวอย่างสั่งรวดเดียวจบ ไม่ต้องตอบคำถามเลย — เปิดโหมดกล้อง + เขียน coil + ยึดพอร์ตคืน

```cmd
echo WRITE | start_all.bat 2 --write --kill
```

ปิดระบบทั้งหมด

```cmd
stop_all.bat
```
